# ADR-047 — 零预算路线图重裁：从「发布产品」到「能力证明资产」

| | |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-09-20 |
| 唯一产地 | 本 ADR + `docs/roadmap.md`（定位声明依据它修订） |

## 背景

原路线图（`roadmap.md` H0→H3 + `dev-plan-0.2-hardening.md`）的成本结构是：
**工程纪律买产品可信度，用户量摊薄它**。而项目所有者是**单人、零分发预算**，
目标是积累架构决策与产品经验，不是运营一个发行版——后半段不会发生，因此整个
前半段也不该全演。同时路线图 §8 的决策点 1（定位主轴）在这个前提下**自动溶解**：
A（可靠层）/ B（Linux-first 产品）/ C（维持自用）三选一的问题只对「争用户」成立。
风险 R2（官方桌面挤压）与 R9（红海）同样不再适用。

## 决策

1. **删除**（烧钱或纯运维苦役）：
   - 0.2-A 签名 / 公证（→ ADR-046）；
   - H3 发行工程；
   - **双上游通道 → 收敂为单一 `next` 线**（→ ADR-048；补丁脆弱性学费已付且
     已文档化，不值得再付一遍）；
   - 安装包体积报告、drift 哨兵、每日定时 CI → 全部改手动（日常提交本来就不
     触发，ADR-030 的每日定时是补偿，补偿也不必要了）；
   - 0.2-D 反馈闭环 / Discussions（无安装基盘 = 无信号）。
2. **保留**（零现金成本、纯工程证据）：全部约 40 个本地验证门禁——
   它们是这个作品集最硬的 artifact。
3. **阶段计划**：
   - **P0**：把既有决策 ADR 化（本目录）+ 单通道收敂。退出条件：
     ≥15 篇可读 ADR + 一个通道。
   - **P1**：一个深潜做到底——Supervisor 状态机 + 崩溃归因 + 性质测试
     （无头、本机 GNU 工具链可跑）。**可证伪承诺**：注入一个「绕过退避」的
     假故障，必须让测试变红；不变红就是没做到底。
   - **P2**：写一份零采用项目的诚实复盘；跑一次零成本单平台无签名发布，
     实测冷启动摩擦（已知陷阱：README 写 Node v18+，而 `MIN_NODE_MAJOR` 是 20）。
4. **完成线**：每个重大决策都有 ADR、每层都有陌生人可跑的验证、复盘存在——
  三条都满足即项目完成，不再追加目标。

## 备选方案与取舍

- **维持原计划、部分加速**：否决。成本结构不变，只是死得快慢的区别。
- **直接停止维护、只留归档**：否决。40 个门禁 + 跨层契约经验是真实能力证据，
  归档等于把已投入的部分作废；且 P1/P2 本身是学习目标。
- **转向上游贡献（roadmap 决策点 1 的 B）**：不采纳为主线。贡献是伴随产物，
  不是目标；等 P1 的深潜产出有独立价值时再议。

## 后果

- 官方桌面版发布后「这个壳还有没有必要」的讨论**溶解**——目标读者不再是
  「装机用户」，决策依据从「采用度数字」变成「能力证据完备度」。
- 删除项涉及在役链路（dual channel、drift、每日 CI），执行时逐项改代码 +
  改守卫 + 改文档，不许只删调用方留下死配置。

## 守卫与证据

- 本 ADR 自身；各删除项对应 ADR-022 / 030 / 046 的「后续」段。
- `npm run verify:drift` 等在役守卫的退役同步记录（改 `package.json` scripts
  时一并核对 `AGENTS.md` §2 命令速查表）。
