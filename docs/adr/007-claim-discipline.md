# ADR-007 — 宣称纪律：状态词表、禁止伪造成功、禁止无声降级

| | |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-09（外部评审后确立，贯穿 A~G 与 0.2 批次） |
| 唯一产地 | `AGENTS.md` §7、`scripts/verify-claims.mjs` |

## 背景

外部评审（2026-09）指出 README / 文档宣称的能力与代码存在落差。最严重的一处不是
「写早了」：`plugin_worker.rs::call_tool` 会**返回伪造的成功结果**（`success: true`），
上层无法通过任何观测手段发现插件工具其实根本没被执行。这不是文档问题，是
**桩实现说谎**。

## 决策

1. 未接线能力必须显式标注，并在 `AGENTS.md` §7.2 对照表登记；禁止用「已实现 /
   已支持」描述未接线能力。状态词只有五种：已接线 / 未接线 / 未实现 / 计划中 /
   已归档，含义互不重叠。
2. **禁止伪造成功**：桩实现被调用必须返回**可辨识的错误**（判据：调用方能否从
   返回值区分「成功」与「未接线」）。2026-09-10 起同时约束 IPC 面——失败必须是
   封套里 `success: false` + 稳定 `error.code`，而不是裸 `false`。
3. **禁止无声降级**：允许降级，但必须写进产物——`MANIFEST.json` 的 `patches[]` 逐条
   记录 `applied / skipped / failed`；脱敏命中次数写进诊断包 `README.txt`；
   日志截断时 `truncated` 必须如实上报；读不到 `MANIFEST.json` 时以
   `manifest_readable: false` + `manifest_error` 如实上报，而不是报错装死。
4. **新增能力先写代码、后登记**，顺序不可颠倒。

## 备选方案与取舍

- **代码即文档，读者自己看**：否决。本仓是三层语言（Rust/Tauri + Node + 前端页面），
  「未接线」在 Rust 侧连 `dead_code` 都不触发（ADR-005 背景），不登记就没人知道。
- **用测试代替登记**：否决。测试证明「某个夹具下成立」，登记回答的是「这个能力有
  没有运行时调用方」，两个问题。

## 后果

- 文档与代码的每次落差都有显式去处；「计划中」（刻意不做的决策）与「未接线」
  （写了没接的欠债）不会互相打掩护。
- 评审/发布前有可执行自查：`grep -rn "⚠️ 未接线\|未实现" AGENTS.md README.md docs/`
  只应命中真实条目（词表、历史盘点、规范引用三类命中属预期内）。

## 守卫与证据

- `npm run verify:claims`（C1~C4：禁止表述 / 状态词三处一致 / §7.2 登记 /
  README 不陈列欠债，夹具为修复前原文，可证伪）。
- 各页面/包路的守卫可参考 ADR-031 的可证伪要求。
