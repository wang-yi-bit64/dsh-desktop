# ADR-031 — 门禁必须可证伪，且不得依赖检出配置

| | |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-09-10 ~ 2026-09-18（各守卫自测逐步固化） |
| 唯一产地 | 各 `scripts/verify-*.mjs` 的 `--self-test` |

## 背景

本仓有约 40 个本地门禁。两条教训来自真实事故：

1. **断言可能是装饰**。一条「X 一定会发生」的跨语言断言，如果没有「打回旧写法
   必须变红」的回退检查，它就只是在复述作者的期望。所以每条这类断言都配一段
   **可证伪性检查**（variants / prune / claims / release-workflow / harness-entry
   均有）。
2. **守卫自己也会因环境静默失效**。某守卫的文本锚点在 `core.autocrlf=true`
   的 CRLF 检出下全部匹配不上，脚本以退出码 1 结束并报「脚本文本已变」——
   **看起来像断言坏了，实际是守卫的匹配依赖了检出配置**。已改为读入时统一
   行尾（`\r\n` → `\n`）。这样的守卫必须在任何检出配置下表现一致。

## 决策

1. 新增「X 一定会发生」这类关于页面/脚本行为的断言，按
   `scripts/verify-harness-inject.mjs` 的模式配**变体回退检查**：把被守护的行为
   打回旧写法，断言必须变红，否则断言是装饰。
2. 守卫**不得依赖检出配置**（行尾、路径分隔符）：读入统一行尾，路径比较用
   `path` 模块语义而非字符串相待。
3. 可证伪夹具优先用**修复前的真实原文**（如 README 被点名的那句禁止表述、
   被打回旧写法的同一份 tauri.conf.json）——用真实事故当夹具，证明的是
   「当时全部门禁全绿而缺陷仍在」，而不是「我的反例构造得对」。

## 备选方案与取舍

- **门禁只报 warning 不报错**：否决。warning 在 CI 日志里等于不存在，
  「假绿」正是本决定要消灭的东西（对比 ADR-020 的 `--error-on-fail`）。
- **用 golden 文件快照比对**：部分场景可用，但快照更新即放行，需要额外纪律；
  本仓选择显式断言 + 夹具，读失败信息的人能直接看懂红在哪。

## 后果

- 每个 `--self-test` 都同时验证「判定函数」与「夹具能红」两件事。
- 写新守卫的成本上升（要构造可证伪变体），这是刻意买的保险。

## 守卫与证据

- 各 `npm run verify:*` 的 self-test 变体（`--self-test` 子命令）。
- `AGENTS.md` §7.3「跨语言断言必须可证伪」条目。
