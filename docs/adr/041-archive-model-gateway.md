# ADR-041 — 多模型工具网关「冻结并归档」

| | |

| 日期 | 2026-09-10 |
| 唯一产地 | `docs/archive/model_gateway_design.md`（退出条件写在该文档） |

## 背景

`crates/dsh-model-gateway` 的 Schema 降级清洗、多厂商方言适配、微秒级基准均已实现
并测试通过，但**无运行时消费者**——与插件隔离同一病灶：为「未来可能有消费者」建的
基础设施。roadmap 决策点 2 还记录了冲突：redesign 文档 §Phase 5 要 Model Gateway 2.0，
外部评审建议复活为 `dsh-provider-compat`。

## 决策

与批次 F 同一裁定：从 workspace 移除（目录 + members + `[workspace.dependencies]`），
设计文档移入 `docs/archive/`。复活必须过归档文档自己的门槛——退出条件 ②
「连续两个 DSH 小版本仍无接线计划」正是当初归档的理由；**接线前置四要素**：
接线点、消费者、失败降级策略、以及「官方覆盖后如何摘除」的回归验证。
四要素写不出来就不开工（roadmap 决策点 2 的 A：暂不复活，仅在 H2 回归语料中
**度量** Tool Calling 兼容痛点是否真实存在）。

## 备选方案与取舍

- **立即复活为独立 runtime 侧组件**：否决。没有真实消费者的兼容层会重蹈归档覆辙；
  Tool Calling 兼容确是真痛点，但「痛点存在」不等于「该由本仓现在解决」。
- **永久不做**（roadmap 决策点 2 的 C）：不采纳为当前结论。痛点待度量，
  但把结论钉死会让将来的证据无处可用。

## 后果

- workspace 少一个零消费者 crate，clippy / 编译 / 认知负担同步下降。
- 「复活」从此是有门槛的动作，不是心情问题。

## 守卫与证据

- `AGENTS.md` §7.2 对应行（🗄️ 已归档，无运行时调用方）。
