# ADR-052 — 双上游通道恢复在役（取代 ADR-048）

| | |
|---|---|
| 状态 | 已接受（决策 1 的 alpha 部分经 [ADR-056](056-alpha-channel-dormant.md) 修订为休眠） |
| 日期 | 2026-09-30 |
| 唯一产地 | scripts/dsh-targets.mjs（目标表）；本 ADR 与 docs/dev-plan-0.8-convergence.md §15 同源 |
| 取代 | ADR-048（单通道收敂） |

## 背景

上游两条线各有真实分发需求，这是 ADR-022 在 2026-09-15 建立双通道的原因。2026-09-20 的零预算重裁（ADR-047）把双通道判为「每条线各持一套补丁与升级流程」的成本项，ADR-048 据此收敂为单一 next 通道，并留下一条尾巴：--channel-of 链路、smoke 的 dsh_target 输入、逐通道 drift 一并退役。

但收敂执行期间出现了三个事实：

1. **双目标机制已经建成**（目标表、按通道分目录的补丁 / vendored / lockfile / staging），保留它继续跑一条线的边际成本接近零——省下的只是「第二份补丁的移植工作量」，而那部分工作量并没有消失，只是从 alpha 线挪到了未来某次重建。
2. **alpha 线上游仍然活跃**，且 0.8 周期的主要工作量（0.2.0 全量补丁移植）本身与通道数无关。
3. **收敂留下的是半保留状态**：目录还在、目标表还在、verify:patches 仍逐目标检查，只有文档与部分调用方按「单通道」写。半保留是 ADR-048 自己点名的最坏形态。

2026-09-29，docs/dev-plan-0.8-convergence.md v1.1 修订 #1 裁定「双通道定稿」，其修订 #9 同时写明「ADR-048 在本周期被取代/延期，需补 superseding 条目」——即该计划**自己承认**缺一条决策记录。维护者于 2026-09-30 确认按 0.8 计划的裁定执行，本 ADR 即为那条缺失的记录。

## 决策

1. **双通道恢复在役**：next 与 alpha 两个目标均为活跃维护项。
2. ADR-022 的机制**原样保留**，不回退也不重新设计：目标表是唯一事实源；桌面 tag 的预发布后缀经 publishChannel 选通道；未知后缀**直接失败**，不回退默认目标。
3. 此前随 ADR-048 停摆的链路恢复为在役：逐通道 drift 对照、smoke 的 dsh_target 输入、patches/alpha、packages/alpha、harness-deps/alpha、逐目标 lockfile。
4. **ADR-048 的收敂决定作废**，但它对成本结构的分析**仍然有效**并被本决定明确接受：维护税用「补丁数趋势 + retireWhen 减法」对冲（见 docs/dev-plan-defect-remediation.md S5）。
5. 若将来要再次收敂，判据回到 ADR-022：出现真实的第二个消费者才重建，不以「省事」为由。

## 备选方案与取舍

- **维持单通道（ADR-048 的决定）**：否决。机制已建成、边际成本为零，且收敂的收益被 0.2.0 移植工作量挤占；真正的成本（第二份补丁）在本周期已经发生。
- **只保留目录、不维护（半保留）**：否决。这正是 ADR-048 自己点名的最坏状态——目录、目标表、守卫都说「有两个目标」，而文档和维护动作只说一个，读者无法判断哪个是真的。
- **恢复双通道并顺手重新设计通道机制**：否决。ADR-022 的机制没有暴露出缺陷，重设计的收益为零而风险是把已验证的链路推倒重来。

## 后果

- 升级、补丁、lockfile 再生成、drift 对照各按通道做一遍——**维护工序翻倍，这是明确接受的代价**。
- 补丁数从「一套」回到「两套」，与「补丁数不增」的长期目标直接冲突。因此 S5 的 retireWhen 减法冲刺是本决定的配套条件，不是可选项：**接受双通道的同时必须接受减补丁。**
- ADR-048 的成本分析文档保留，作为未来再次评估收敂时的输入（它的算术没错，只是当时的结论在当前前提下不再成立）。

## 守卫与证据

- npm run verify:targets —— 目标表自检（34 项）：未知通道必须失败、不得回退默认目标。
- npm run verify:patches —— 逐目标的分级与包名/版本一致性（当前 2 个目标）。
- npm run verify:plan-facts —— 计划文档的版本锚点与批次状态账本自洽。
- 本 ADR 与 docs/dev-plan-0.8-convergence.md §15 互为证据；ADR-048 的状态已改为「已被本 ADR 取代」。

## 修订（2026-09-30）

决策 1「next 与 alpha 两个目标均为活跃维护项」由 [ADR-056](056-alpha-channel-dormant.md) 部分修订：
**alpha 线休眠**（不发布、不追漂移，补丁与 vendored 冻结保留），next 线维持在役；机制与目录保留的
决定不变。直接诱因是通道化首发（v0.7.1-rc.1）实测「在役的 alpha 零投递」——守卫每天红、维护动作
永远不会来，属于用红噪音训练人无视红灯。恢复在役的条件与版本约束（须严格大于当时最高 rc tag）
见 ADR-056。
