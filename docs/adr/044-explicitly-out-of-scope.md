# ADR-044 — 明确不做清单（防止范围爬升）

| | |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-09（随各计划「明确不做」节汇总固化） |
| 唯一产地 | 各 dev-plan 的「明确不做」节 + `AGENTS.md` §5 P2/P3 归档行 |

## 背景

壳层项目最容易的死法是范围爬升：上游做什么都想跟、社区提什么都说好、每加一个
「小功能」都看起来无害。把不做的事**连同理由**写下来，下一次讨论才有锚点。

## 决策（清单）

| 不做 | 理由 |
|------|------|
| 重写 Harness UI | 本仓是壳，UI 归上游 / 官方（ADR-006） |
| 为 Harness 远程 origin 开反向 IPC | 命令面收紧是安全边界（ADR-005/006） |
| 遥测 / 使用统计 | 与「Nothing is uploaded anywhere」姿态冲突；采用度用 GitHub releases / stars / issues 作代理信号 |
| 公网隧道（手机桥外网化） | 与 local-first 安全姿态冲突——自动在公网暴露 Harness 是姿态级让步（0.2-决策点 4；roadmap §10 亦把移动端排除出核心竞争力） |
| 引入 oRPC / tRPC | 对端是 Rust，TS 类型推导收益失效，还多一层运行时 |
| 皮肤 / 桌面宠物 / SSH 面板 | 非差异化，且与「可运维 / 可信赖」定位相悖 |
| PPT 模式 / Agent 预设管理 / 模型供应商管理 | 官方桌面版的主场（两套评估独立得出同一结论） |
| 为「可能有用的未来 UI」保留死命令 | 死代码要么接上、要么删掉（ADR-005） |
| 300MB 瘦身另起主线 | 已有长期方案（`harness-packaging-and-compatibility.md`），演练数据反哺它，不重复立项 |

## 备选方案与取舍

- **不写清单，遇事再议**：否决。范围爬升从来不是一次大决定，而是一百次
  「这个看起来无害」。清单让每次说「不」有出处。
- **写成永久结论**：部分条目（遥测、隧道、oRPC）是姿态级的不做；
  另一些（桌面宠物类）是优先级不做。清单按理由分级，不留「永远」的模糊表述。

## 后果

- 新需求进来先对清单；确要推翻某条，改清单本身（留痕），而不是默默破例。
- 零预算重裁（ADR-047）后清单进一步扩大：签名/公证、发行工程、反馈闭环、
  双通道维护均进入删除侧。

## 守卫与证据

- `dev-plan-disconnected-points.md` §6、`dev-plan-0.2-hardening.md`「明确不做」、
  `roadmap.md` §10 三处同源清单。
- `AGENTS.md` §5（P2/P3 归档 + P4 边界口径）。
