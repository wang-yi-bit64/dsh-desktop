# ADR-032 — 壳内页面运行时冒烟：DOM 桩真跑真点，含封套解包检查

| | |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-09-10（批次 E 后建立） |
| 唯一产地 | `scripts/verify-shell-pages.mjs` |

## 背景

批次 E 把 17 个命令改成 `IpcEnvelope<T>` 后，`frontend/updates.html` **当场断了**
而且没有任何编译错误、没有异常、没有日志：`apply` 拿到的是封套而非快照，
`snapshot.phase` 恒为 `undefined`，于是每次调用都静默早退、整页永不渲染。
静态比对（verify-ipc-surface）看得见「命令有调用方」，看不见「载荷形状对不上」。

## 决策

建立壳内页面的**运行时**冒烟：在 DOM 桩里真跑内联脚本、逐个点按钮。检查项
P1~P6：

- P1 引用可解析；P2 脚本不抛错；P3 命令已注册；
- P4 **按钮都挂了监听**（抓「HTML 留了按钮但脚本忘了绑」）；
- P5 模板 id 前缀可解析（抓 `getElementById` 拿到 `null` 导致整页监听失效）；
- P6 **命令结果解包了封套**（抓「调用了命令却把封套当载荷用」）。

并确立纪律：**改命令返回形态属于破坏性变更，必须过 `npm run verify:shell-pages`**。

## 备选方案与取舍

- **靠 L2 GUI 冒烟覆盖页面**：否决。L2 起真实窗口、成本高，且它验证的是
  「页面能加载」，不会去点每个按钮再断言监听存在。
- **把页面逻辑编译进 Rust 测试**：否决。页面是内联脚本 + HTML 的混合体，
  编译化要么重写要么只覆盖一角。

## 后果

- 它抓到的两类缺陷（封套当载荷、按钮没绑）都是**静默**的，没有它就只能靠人眼。
- 新增页面/新命令形态变更后必跑；新增检查项要按同一格式在脚本头部注释登记。

## 守卫与证据

- `npm run verify:shell-pages`（CI 与 release preflight）。
- `scripts/verify-shell-pages.mjs` 头部注释写明「它查什么、不查什么」。
