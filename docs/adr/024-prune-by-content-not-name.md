# ADR-024 — 依赖树瘦身判据是「内容」不是目录名

| | |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-09-11 |
| 唯一产地 | `scripts/prune-harness-deps.mjs` |

## 背景

`prepare:harness` 会把组装好的 `node_modules` 里「名字像开发产物」的目录
（`test` / `docs` / `doc` / `example` …）**整目录删除**以缩小安装包。这条按名字
判定的规则是错的：`doc` 在某些包里恰好是**运行时路径**。

2026-09-11 定位的真实事故：`yaml/dist/doc/` 被整个删掉，而那里装的是
`directives.js` / `Document.js` 等运行时模块，于是 Harness 一启动就崩：

```
Error: Cannot find module '../doc/directives.js'
```

这个缺陷**没有任何静态检查能发现**——打包、签名、安装、`tauri build` 全部成功，
只有真正启动才报错，即「装得上、起不来」。它能存活这么久，是因为 CI 直到
2026-09-10 才加「真实资源树 L1 烟雾」，而那条烟雾当时又被更早的红灯连续挡住。

## 决策

判据改为**目录内是否含运行时模块**（`.js`/`.cjs`/`.mjs`/`.node`/`.wasm`/`.json`）：
命中名字只是必要条件，**含运行时模块时只递归进去删文件，绝不整目录删除**。
取舍明确：误删只会得到一个起不来的包，少删只是少省一点体积——判据一律偏向
「宁可不删」。

## 备选方案与取舍

- **维护一份「这些包的这些目录要保留」白名单**：否决。上游改版即失效，
  白名单会静默腐烂；而且把「默认删」的风险留给了漏登记。
- **不瘦身，接受体积**：否决（当时）。瘦身收益真实存在；内容判据已经消除了
  误删风险，不需要连收益一起放弃。

## 后果

- 实测（真实 `yaml` 包，203 → 153 个文件）：`dist/doc/directives.js`、`Document.js`
  存活，同目录 5 个 `.d.ts` 仍被删除。
- 整个 staging 内有 **42 个**「名字像开发产物但含运行时模块」的目录，旧判据会
  全部误删——自测用这个数字的可复现性钉住判据。

## 守卫与证据

- `npm run verify:prune`：自测带**可伪证性检查**——把旧判据作用于同一棵树必须
  复现出「`dist/doc` 被删」，否则自测本身失效。
- 真实资源树 L1 烟雾（`smoke.yml` scope=assembled/full）在真实启动路径上兜底。
