# ADR-022 — 双上游通道 next / alpha（已被 ADR-048 取代）

| | |
|---|---|
| 状态 | **已被 ADR-048 取代**（保留供追溯） |
| 日期 | 2026-09-15 |
| 唯一产地 | `scripts/dsh-targets.mjs`（在役期间） |

## 背景

两条上游线各有真实分发需求：`next` 追稳定特性，`alpha` 追上游预发布（文档预览等）。
最初只有单一默认目标，组装哪条线靠人记住——漏传 `--dsh-target` 就会组装另一棵
资源树，而所有步骤都是绿的。

## 决策（原决定）

1. **唯一事实源是 `DSH_TARGETS` 表**（目标名 ↔ npm dist-tag ↔ DSH 版本），
   `prepare-harness.mjs` 不再写死版本，按 `--dsh-target=<name>` 推导该目标的
   补丁目录、vendored 目录与 staging 目录。
2. **桌面版本号的预发布后缀就是通道名**：`release.yml` preflight 用
   `--channel-of "$VERSION"` 从 tag 反推该组装哪个运行时。**未知通道直接失败**，
   不回退默认目标——静默回退会产出「版本号说 beta、运行时却是 next 线」的包，
   而这类错配只有用户装上才会发现。
3. 补丁分级表按**包名**索引（`patch-layers.mjs`），新增一条上游线不需要动它；
   只有引入新包才补登记。
4. 目标来源三优先级：CLI 参数 > `DSH_TARGET` 环境变量 > 默认目标
   （环境变量分支的由来见 ADR-027）。

## 备选方案与取舍

- **单一默认目标**（原状）：否决理由是需要同时分发 alpha 线；但零预算重裁后
  这个前提消失，见 ADR-048。
- **tag 之外再声明一次通道**（workflow input）：否决。同一事实两处声明必然漂移；
  版本号后缀已经是天然的单一声明点。

## 后果

- 「版本号 ↔ 运行时通道」的错配被 preflight 拦在组装 300MB 之前。
- 两条线的补丁数可以不同（净减少是补丁退役机制想要的方向，不为「一样多」加回
  已退役补丁）。
- 长期代价：每条线各持一套补丁 + 一套升级流程——这正是重裁时压垮它的成本结构。

## 后续

被 **ADR-048** 取代：收敂为单一 `next` 通道，`--channel-of` 链路、smoke 的
`dsh_target` 输入、逐通道 drift 随之退役。`dsh-targets.mjs` 的推导逻辑与
`patches/<target>/` 目录结构可保留为重建底座（成本低），但不再是活跃维护项。
