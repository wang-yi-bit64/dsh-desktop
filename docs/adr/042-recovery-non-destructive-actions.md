# ADR-042 — 恢复页只接非破坏性动作；插件卸载/禁用记为计划中

| | |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-09-10（批次 C；证据链在 `dev-plan-disconnected-points.md` §3） |
| 唯一产地 | `src-tauri/frontend/plugin-recovery.html`、`commands.rs::recovery_action` |

## 背景

恢复页（`plugin-recovery.html`）要做「插件故障后的处置」。原计划建议 B 方案
（「卸载」改为「禁用」：目录改名 `<name>.disabled`，可逆）。**经代码核验被否决**：
改名会被冷启动投影（`projectGenerations()`）静默还原；而唯一真正生效的「禁用」
写法（从 `desired.json` 摘除条目）会触发 `sweepRegistry()` **真删除**该 generation
目录。即只剩「假装禁用（会被还原）」与「真删除」两条路，**没有真正的可逆解除挂载**。

## 决策

决策点 4 采 **A**：只接 `safe-mode` / `restart` / `show-log` / `quit` 四个**非破坏性**
动作，卸载按钮从页面移除，卸载能力记为 🕓 计划中（依据是上游是否提供停用语义）。
撤销 A 的前提：上游提供插件 disable / quarantine 语义（0.2-决策点 3 / 批次 0.2-B4
的重新核验），届时按 A→B 转换。

三条配套（缺一条仍是谎言）：

1. **数据走命令面不走 URL 传参**：页面调 `recovery_status` 拿数据；原先为此带的
   `urlencoding` 函数一并删除——数据本来就要经命令面校验 origin，绕一道路没有收益。
2. **按钮必须检查封套 `success`，失败显式提示**；未知动作返回 `E7002` 而非
   静默 `false`（裸 `false` 正是「点了没反应」的根因，ADR-005 / ADR-007）。
3. **错误页仍是第一落点，不做 `on_failed` → 恢复页的自动路由**：插件故障不再走
   错误页的话，那条「疑似插件故障 → 进入安全模式」分支会**立刻变成新的死 UI**
   ——一个刚修好的 bug 以另一种形式复活。改为错误页上增加「插件恢复…」按钮
   通往恢复页；两页职责分明（错误页=出了什么事 + 一键救命；恢复页=细节 + 多种处置）。

## 备选方案与取舍

- **B（改名禁用）**：否决，见背景——不可逆性被伪装成可逆，比没有更糟。
- **C（完整卸载 + UI 二次确认）**：否决。不可逆操作，且要在**恢复态**
  （UI 可能不完整）下做安全确认，风险最高。
- **D（恢复页整体下线）**：否决。面最小、零谎言，但放弃上游已有的诊断交互，
  属功能回退。

## 后果

- 恢复页四个按钮全部有可达后端与可见反馈。
- 「插件禁用」成为**条件化计划中**：不是偷懒，是等上游语义；核验日期到期要重走
  证据链（0.2-B4），不能永远挂着。
