# ADR-055 — 保留每日 CI 与上游漂移哨兵（修订 ADR-047 的删除清单）

| | |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-09-30 |
| 唯一产地 | `.github/workflows/ci.yml` 与 `.github/workflows/drift.yml` 的 `schedule` |
| 修订 | ADR-047「删除」清单第 2 项（安装包体积报告 / drift 哨兵 / 每日定时 CI → 全部改手动） |

## 背景

2026-09-20 的零预算重裁（ADR-047）把「安装包体积报告、drift 哨兵、每日定时 CI」一并划入删除侧，
理由是零预算 + 无安装基盘。但执行时只落了一部分：**代码侧的 schedule 一直在**
（`ci.yml` 的 `41 2 * * *`、`drift.yml` 的 `17 3 * * *`），而 ADR 说它们该删。

这个矛盾在 2026-09-30 的独立评审里被记为 D3（决策账本冲突）的一部分：**代码保留、文档说删**，
读者无法判断哪个是真的。本 ADR 是那条缺失的裁决。

## 决策

1. **保留**每日 CI（`ci.yml`）与上游漂移哨兵（`drift.yml`），两者均为**在役能力**。
2. **ADR-047 的删除清单第 2 项作废**（由本 ADR 修订），其余项不受影响。
3. 发布前**仍须手动 dispatch** `ci.yml` 与 `smoke.yml scope=full`（ADR-030 的纪律不变）。
   每日定时跑的是静态门禁 + clippy + 单测，**不跑冒烟**（起窗口 / 组装 300MB），
   因此它**不能替代**发布前那两次手动 dispatch。
4. drift 哨兵的真检查会因「上游领先」而红，那是**待规划升级**的信号而非提交缺陷，
   因此不进 PR 门禁；CI 只跑它的自测。这条维持 ADR-030 的既有分工。

## 备选方案与取舍

- **按 ADR-047 原文删掉两处 schedule**：否决。它们是「日常提交零自动化」之下**唯一**能自动发现
  「main 的 HEAD 长期没人验过」的网；删掉等于把静态门禁 + 单测的最后一层兜底也交给人的记性。
  现金成本为零（公开仓库的 Actions 免费额度），而 release 的 preflight 只看秒级静态门禁、
  看不见单测与 clippy。
- **保留但只在失败时通知、不跑真检查**：否决。drift 的价值就在真检查；改成静默运行等于删掉它，
  却让「还有哨兵」这句话继续成立——那是 ADR-007 所禁的无声降级。
- **保留 ci 定时、删 drift 定时**：否决。两者守的是不同的东西（前者：本仓提交是否还能通过；
  后者：上游是否已经领先到补丁面要重做），没有理由只留一个。

## 后果

- GitHub 上每天两次定时运行继续存在（非整点错峰，失败通知是唯一的叫人手段）。
- ADR-047 的「零预算」重裁在这一点上被**明确推翻**：保留的判据是「零现金成本 + 不可替代的
  最后一道网」，而不是「重裁错了」——ADR-047 的其余删除项（签名 / 公证、发行工程、CLI 上传通道、
  反馈闭环）依然有效。
- 「日常提交零自动化」的口径不变：定时任务是**补偿机制**，不是把 push 触发加回来。

## 守卫与证据

- `ci.yml` 与 `drift.yml` 的 `schedule` 块是本决定的现场证据；两个文件同时保留 `workflow_dispatch`
  供手动触发（`gh workflow run ci.yml --ref main`）。
- 发布前的两次手动 dispatch 写在 `docs/release-runbook.md`（原 AGENTS.md §8.5）。
- 本 ADR 与 ADR-030 的分工：ADR-030 定义「为什么日常零自动化」，本 ADR 定义「补偿机制保留哪两项」。
